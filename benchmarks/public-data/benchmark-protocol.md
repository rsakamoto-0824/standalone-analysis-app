# ベンチマークの進め方

## 共通

1. [一覧](README.md)からデータを選び、個別のREADMEで対象・列・注意点を確認する。CSVのヘッダーは1行目。
2. データセットID、アプリのコミット、MATLABの版、選択列、学習条件、乱数seed、処理時間を結果に記録する。条件を比較するときは分割・探索予算を揃える。
3. 正解ファイル、行番号、分割ラベルを説明変数に入れない。条件選びに最終テストデータを使わない。

## 多目的最適化

各フォルダの`data.csv`は、入力と複数の評価値が揃った候補表です。`Y_`で始まる列が目的変数です。最小化・最大化は個別READMEと`catalog.json`に記載しています。UCIの目的方向は本ベンチマークの例として指定し、MOOTの方向は元の列名末尾の符号を保持しています。

まず汎用回帰学習で、推奨する説明変数とすべての目的変数を選んでモデルを比較できます。複数目的の同時選択は目的ごとの別モデルの学習です。最適化アルゴリズムの性能確認は、このデータの候補を対象に、同じ予算で選択・評価する手順を別途用意して行います。この追加にはアプリへの最適化機能の実装や、自動採点結果は含めていません。

`split.csv`は学習用と最終評価用の行を指定します。汎用回帰画面のランダムな交差検証が、この分割表を自動で適用するわけではありません。行番号に従って学習用CSVを作り、学習後は保存モデルで推定する機能へテスト用CSVを読み込むか、検証用の処理で分割を適用してください。分割行の除外・抽出以外に、全行による標準化や欠損補完を事前に行わないようにします。

- Energy Efficiency等は同じ入力値の組を同じ群にして約80/20へ分割しています。XOMOの定数列`SCED`と`TOOL`は、元データに残し、説明変数の推奨一覧からは外しています。
- Gas Turbineは公開元に合わせて2011～2013年を学習、2014～2015年をテストとします。全期間を混ぜたランダム分割は、時系列での汎化を測れません。完全重複7行を含め、元の計測行を削除せず保持しています。
- 成膜条件のような実際の操作量を測定値から区別し、この候補表での結果を実機の推奨条件と解釈しないでください。配合・形状の制約、離散設定、環境条件があるため、各列の最小～最大の箱の中を自由に探索できるとは限りません。

`reference_pareto_indices.csv`は、公開された**全候補内**で他の候補に劣らない行の番号です。少なくとも1目的で改善し、他のすべてで同等以上なら「支配する」と定義し、同じ目的値の行はすべて残します。番号は`data.csv`のデータ先頭行を1とし、ヘッダーを数えません。連続空間全体の真のパレート面ではありません。データによって非劣解が少ないケースも含みます。

探索の比較では、初期に評価する行を共通にし、残りの真値をモデルから隠して、一定の追加評価回数ごとに非劣解を記録します。最終的に選んだ候補はCSVの実測／公開値で採点します。候補表と違う入力を提案した場合、このデータだけでは真値を返せません。

確認する指標の例は、目的ごとのテストRMSE・決定係数、候補内パレート解の発見率、Hypervolume、実行時間です。Hypervolumeの参照点と各目的の尺度は実行前に固定して記録します。テスト行だけを候補集合とする場合、正解もテスト行の範囲で計算し直してください。

## 因果探索

すべて公開済みの合成データで、独自に生成したデータではありません。連続値の2～20変数で、アプリのPC・DirectLiNGAMへ数値列として読み込めます。**読み込めることと、手法の前提を満たすことは別です。**

1. CSuiteは`train.csv`、GraN-DAGは`data.csv`を因果探索画面で開き、X0から始まる列をすべて選ぶ。CSuiteの元のtrain/val/test分割は保持しており、条件選択にval、最終確認にtestを使用できる。
2. 最初の比較では、有意水準0.05・PCの条件づけ最大数3など共通条件を決め、条件と処理時間を記録する。20変数で条件づけの上限を小さくした場合、完全なPCの結果とは区別する。
3. 正解と列を対応させて、辺の有無、向き、余分な辺、検出漏れを採点する。観測列を並べ替える場合、正解行列も同じ順に行・列を並べ替える。公開データの列順への依存を確認するため、複数の列順でも比較するとよい。
4. CSuiteの別分割で推定がどの程度変わるかも確認する。データセットごとの性質と変数数を示し、前提の異なる10件の平均だけで手法の優劣を決めない。

正解隣接行列は`reference_adjacency.csv`で、行Xi・列Xjが1ならXi→Xjです。行ラベル列はなく、観測CSVと同じ列順です。`reference_edges.csv`のsource/targetもこの向きです。正解グラフや介入データを学習用の観測値と結合しません。

PCは向きを確定できない辺を残せるため、骨格のPrecision/Recall/F1と向きの評価を分けます。両方向が1の無向辺を、逆向きの誤りを含む2本の有向辺として数えないでください。GraN-DAGの`reference_cpdag.csv`は公開元の参照であり、PCの比較に使えます。DAGに対するSHDを使う場合は、反転・無向辺を何点とするかも記録します。

CSuite `lingauss`は2変数の向きが観測データだけでは決まらない例です。`linexp`は線形・非正規ノイズのためDirectLiNGAMの基本条件を試せます。`nonlingauss`は非線形だが共分散が0になる例です。Simpson系・GraN-DAGの非線形GPなどは、アプリの偏相関PC・線形DirectLiNGAMが想定する関係から外れるストレステストとして扱います。既知のDAGが付いていても、観測値だけで全方向を識別できるという意味ではありません。

## 再取得と確認

CSVは取得済みなので、利用時にPythonやインターネットは不要です。生成・検査をやり直す場合はPython **3.14.5以上**とNumPy **2.4.6**を使用します。今回のデータ変換はPython 3.14.6 / NumPy 2.4.6で実施しています。

WindowsのPowerShellで、リポジトリを開いて実行します。

```powershell
py -3.14 -m pip install -r benchmarks/public-data/_src/requirements.txt
py -3.14 benchmarks/public-data/_src/prepare_datasets.py --verify
# 元データの再取得と再変換（ネット接続が必要）
py -3.14 benchmarks/public-data/_src/prepare_datasets.py
```

再取得先は公式URL・固定コミット／リリースに限定し、元ファイルのSHA-256が変わっていたら停止します。キャッシュはOSの一時フォルダに作成します。任意の場所は`--cache <フォルダ>`で指定できます。データの数値・順序は変更せず、補間・外れ値除去・標準化はしません。データを変更した独自の結果は別フォルダに保存してください。

アプリの読込み処理だけを確認する場合、MATLABでリポジトリを現在のフォルダにして実行します。

```matlab
addpath(fullfile('benchmarks', 'public-data', '_src'));
report = check_app_import;
```

検査結果は[validation.json](validation.json)と[アプリ読込みの確認記録](matlab-import-validation.json)を参照してください。これらはデータの整合性・読込みの記録です。最適化・因果探索の精度、MATLAB R2025b / Windowsでの動作を確認した記録ではありません。
